# B200 (sm_100 / Blackwell) results

All experiments run on a Modal-provisioned single B200 (cap (10,0), 192 GB HBM,
torch 2.9.1+cu128, triton 3.5.1). Modal entry points live under `modal/`:

- `modal/run_correctness_b200.py` — 3 pytest files
- `modal/run_attn_b200.py` (`mode=full`) — `benchmarks/attn_only_all_n.py` sweep
- `modal/run_gemma4_26b_cossim.py` — Gemma-4-26B-A4B per-layer cos-sim with `--all-layers`

## B200 vs H100 codegen workarounds

Triton 3.5.1 has no TMA on sm_100 yet, so the H100 configs that fit at
`num_stages=2` overflow B200's 232 KB dynamic SMEM, and certain `wgmma`
layouts at `D=512` fault with misaligned addresses. Two gates patched into
`flash_attn/attention.py`:

- `_stages(default)` — clamps `num_stages` to 1 on `cap[0] >= 10`. Used at every
  triton kernel launch in the autograd path AND in the direct call wrapper
  `attention_flash_gqa()`.
- `is_blackwell` BLOCK_Q halving — for `D >= 512`, fwd uses `BLOCK_Q=32`
  (vs 64 on H100); dQ uses `BLOCK_KV_BW=32` (vs 64); packed dKV uses
  `BLOCK_Q_DKV=32` (vs 64).

`tests/test_packed_dkv.py` calls the inner kernels directly, so it gets the
same B200-aware block selection in `run_forward_with_lse` / `run_dkv_split` /
`run_dkv_packed` (`_is_blackwell()` helper at top of file).

## 1. Module-level correctness — all PASS

Modal job: `modal run modal/run_correctness_b200.py` (~37s on cold container,
exit 0). Three test files, all green on B200:

| File | Cases | Result |
|---|---|---|
| `tests/test_packed_dkv.py::test_correctness` | 7 configs (D=256 + D=512, causal ± SWA) | PASS |
| `tests/test_image_group_mask.py` | 10 (fwd + bwd, image OR-mask paths) | PASS |
| `tests/test_noncausal_vision_shape.py` | 9 (vision-bidirectional fwd/bwd, adapter routing) | PASS |

`test_packed_dkv` D=512 cases originally crashed with `CUDA_ERROR_MISALIGNED_ADDRESS`
because the test's hardcoded `BQ=16` for D=512 hit the same `wgmma` layout bug
that required halving `BLOCK_Q` in the production fwd path. Fix mirrors
production: on B200 use `BQ=32, BKV=16` for the dKV kernels and `BQ=32` for fwd.

### Notes

- **D=256 SWA scales well**: Triton wins from `N≥2K` and the gap widens with N
  — at `N=32K` Config B (Gemma-4-E2B real SWA) reaches **17.6× bwd**, **17.2× F+B**.
  This is the production hot path.
- **D=512 fwd loses to SDPA** (~0.55-0.74×): cost of the BLOCK_Q=32 workaround
  (half the H100 tile). SDPA's cuDNN backend has full sm_100 tuning; we don't.
  bwd still wins (1.28-1.52×) because the bwd path was already register-bound
  enough that the smaller tile is closer to optimal.
- Once Triton ships TMA / proper sm_100 autotuning, raising BLOCK_Q back to 64
  on D=512 should close the fwd gap without source changes (the gate already
  branches on `cap[0] >= 10`).

### Shape

- Smooth monotonic drift through layer 0 → ~23 (cos 1.0 → 0.91), recovers to
  0.985 by the final hidden state. Same shape as on H100 — the residual /
  norm structure pulls representations back together at the top of the stack.
- Lowest cos = 0.910 at layer 23 (still well above the 0.9 threshold);
  rel_frob peaks ~0.42 mid-stack.
- Final layer cos = 0.984; logits cos = 0.989; top-1 match 100%.
- Gate (`layer-1 cos > 0.9999`, `top1 ≥ 0.95`) PASSES with 0.999989 / 100%.
